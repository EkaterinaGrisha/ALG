# Задача «Легенда об Икаре» (интерактивная)

Файл решения: [`icarus.py`](../icarus.py). Отправлять можно на Python 3.13.2 или PyPy:
программа задаёт не больше 118 запросов.

---

## 1. Условие простыми словами

Есть два неизвестных числа N и M (`1 ≤ N ≤ M ≤ 10¹⁸`). Известно только, что
`M − N > N`, то есть **M > 2N**. Нужно узнать N.

Узнавать можно с помощью вопросов. Мы называем высоту `h` (от 1 до 10¹⁸), а система отвечает:

- `wet`, если `h < N` («слишком низко, крылья мокрые»);
- `ok`, если `N ≤ h ≤ M` («нормально»);
- `fail`, если `h > M` («слишком высоко, воск растаял»). Это **проигрыш**, после него
  программа должна сразу завершиться.

Вопросов можно задать не больше 200. Когда N найдено, выводим `! N`.

---

## 2. Краткая теория

### 2.1. Интерактивная задача

В обычной задаче программа получает весь ввод сразу и печатает весь вывод. В
**интерактивной** программа ведёт диалог с проверяющей программой (её называют
**интерактор**): напечатала вопрос, прочитала ответ, напечатала следующий вопрос и так далее.

Важная техническая деталь — **flush** («сброс буфера»). Python копит выводимый текст
в памяти (в **буфере**) и отправляет его порциями, так быстрее. В интерактивной задаче
это ломает диалог: наш вопрос застрянет в буфере, интерактор его не увидит и будет
ждать вечно. Тестирующая система выдаст вердикт «Idleness limit exceeded» (программа
бездействует). Поэтому после **каждого** вопроса вызываем `sys.stdout.flush()`.

### 2.2. Двоичный поиск

Если известно, что N лежит в отрезке `[lo, hi]`, и есть вопрос «N ≤ mid?», то
спрашиваем про середину и отбрасываем половину отрезка (подробнее в
[разборе задачи 1](01_two_of_three.md#24-двоичный-бинарный-поиск-по-ответу)). Здесь
ответ `ok` на высоту `mid` означает `N ≤ mid`, а ответ `wet` — что `N > mid`.

**Проблема:** если сразу искать по `[1, 10¹⁸]`, первая середина будет около 5·10¹⁷.
Она может оказаться выше M, и мы получим `fail`. Значит, сначала нужно безопасно
найти высоту, которая точно не выше M.

### 2.3. Экспоненциальный поиск (поиск удвоением)

Спрашиваем высоты 1, 2, 4, 8, 16, …, удваивая каждый раз, пока ответ `wet`. Такой
приём называют **экспоненциальным** (или «галопирующим») поиском: шаг растёт как степень двойки.

**Почему это безопасно.** Пусть на высоту h ответили `wet`. Значит, `h < N`. Тогда
следующая высота `2h < 2N < M`, и она не выше M. Ответа `fail` быть не может!
Именно для этого в условии дано `M − N > N`.

Как только пришёл ответ `ok` на высоту `h = 2ʲ`, мы знаем:

- прошлая высота `2ʲ⁻¹` дала `wet`, значит `N > 2ʲ⁻¹`;
- текущая дала `ok`, значит `N ≤ 2ʲ` и при этом `2ʲ ≤ M`.

### 2.4. Подсчёт числа вопросов

- **Удвоение:** так как `M ≤ 10¹⁸` и `M > 2N`, то `N < 5·10¹⁷ < 2⁵⁹`. Значит, удвоение
  остановится не позже высоты 2⁵⁹: это не больше 60 вопросов (1, 2, 4, …, 2⁵⁹).
- **Двоичный поиск** на отрезке `(2ʲ⁻¹, 2ʲ]` длины `2ʲ⁻¹`: не больше `j − 1 ≤ 58` вопросов.
- **Всего** не больше 118, а разрешено 200.

## 3. Суть решения (без кода)

1. **Удвоение.** Спрашиваем 1, 2, 4, …, пока ответ `wet`. Каждый такой запрос безопасен,
   потому что M > 2N.
2. После первого `ok` на высоту h знаем, что N лежит в `(h/2, h]`. Все высоты в этом
   отрезке не выше h, а h не выше M.
3. **Двоичный поиск** в этом отрезке. Он тоже безопасен, так как мы не поднимаемся выше h.
4. Печатаем `! N`.

## 4. Логика по шагам с трассировкой

Пример из условия: пусть загадано **N = 10, M = 21** (M > 2N = 20 ✓).

**Этап 1, удвоение:**

| Вопрос h | Ответ | Почему | Вывод |
|----------|-------|--------|-------|
| 1 | wet | 1 < 10 | N > 1 |
| 2 | wet | 2 < 10 | N > 2 |
| 4 | wet | 4 < 10 | N > 4 |
| 8 | wet | 8 < 10 | N > 8 |
| 16 | ok | 10 ≤ 16 ≤ 21 | N ≤ 16 |

Теперь N в отрезке `[9, 16]`, и высота 16 безопасна.

**Этап 2, двоичный поиск** (`lo = 9`, `hi = 16`):

| lo | hi | mid | Ответ | Новый отрезок |
|----|----|-----|-------|---------------|
| 9 | 16 | 12 | ok (N ≤ 12) | [9, 12] |
| 9 | 12 | 10 | ok (N ≤ 10) | [9, 10] |
| 9 | 10 | 9 | wet (N > 9) | [10, 10] |

Отрезок сжался в точку: печатаем `! 10`. Всего 8 вопросов.

В условии показан другой порядок вопросов (8, 11, 9, 10). Это нормально: подойдёт
любая стратегия, которая не превышает M и укладывается в 200 вопросов.

## 5. Код

```python
import sys


def ask(h):
    sys.stdout.write(f"{h}\n")
    sys.stdout.flush()
    r = sys.stdin.readline().strip()
    if r != "ok" and r != "wet":
        # «fail» (или конец ввода) — нужно немедленно завершиться
        sys.exit(0)
    return r == "ok"


def main():
    # Удвоение: если h < N, то 2h < 2N < M, значит следующий запрос безопасен.
    prev = 0
    h = 1
    while not ask(h):
        prev = h
        h *= 2
    # N в (prev, h], и h <= M — бинпоиск внутри безопасен.
    lo, hi = prev + 1, h
    while lo < hi:
        mid = (lo + hi) // 2
        if ask(mid):
            hi = mid
        else:
            lo = mid + 1
    sys.stdout.write(f"! {lo}\n")
    sys.stdout.flush()


main()
```

## 6. Построчный разбор кода

```python
def ask(h):
    sys.stdout.write(f"{h}\n")
    sys.stdout.flush()
```

- Функция одного вопроса. Печатаем высоту и перевод строки.
- `flush()` — обязательный сброс буфера, чтобы интерактор сразу увидел вопрос.

```python
    r = sys.stdin.readline().strip()
```

- Читаем одну строку ответа. `.strip()` убирает перевод строки и пробелы по краям.

```python
    if r != "ok" and r != "wet":
        sys.exit(0)
    return r == "ok"
```

- Если пришло что-то кроме `ok`/`wet` (то есть `fail` или конец ввода), сразу
  завершаемся, как требует условие. При правильном алгоритме этого не случается.
- Возвращаем `True`, если ответ `ok` (то есть `N ≤ h`), и `False`, если `wet` (`N > h`).

```python
    prev = 0
    h = 1
    while not ask(h):
        prev = h
        h *= 2
```

- Этап удвоения. `prev` хранит последнюю высоту с ответом `wet` (0, если таких не было).
- Пока ответ `wet`, запоминаем h в `prev` и удваиваем h.
- Цикл кончается на первом `ok`.

```python
    lo, hi = prev + 1, h
```

- N строго больше `prev` (там было `wet`) и не больше `h` (там `ok`), поэтому отрезок `[prev + 1, h]`.
- Если `ok` пришёл сразу на h = 1, получится `lo = hi = 1`, и поиск не понадобится: N = 1.

```python
    while lo < hi:
        mid = (lo + hi) // 2
        if ask(mid):
            hi = mid
        else:
            lo = mid + 1
```

- Обычный двоичный поиск наименьшей высоты с ответом `ok`. Это и есть N.
- `ok` на `mid` значит `N ≤ mid`, поэтому `hi = mid`; `wet` значит `N > mid`, поэтому `lo = mid + 1`.

```python
    sys.stdout.write(f"! {lo}\n")
    sys.stdout.flush()
```

- Печатаем ответ в требуемом формате `! N` и снова сбрасываем буфер.

## 7. Сложность

- **Вопросов:** `O(log N)`, не больше 60 + 58 = 118.
- **Время и память:** `O(1)` на вопрос. Программа почти всё время ждёт ответов интерактора.

---

## 8. Частые ошибки

1. **Забыть `flush()`.** Тогда программа и интерактор ждут друг друга, и получается
   вердикт «Idleness limit exceeded».
2. **Двоичный поиск сразу по `[1, 10¹⁸]`.** Середина может оказаться выше M, и будет `fail`.
3. **Начать удвоение с 0.** Высота должна быть не меньше 1, а `0 · 2 = 0` ещё и зациклит программу.
4. **Шаг больше удвоения** (например, умножать на 3). Безопасность держится ровно на
   `2h < 2N < M`: при утроении `3h` уже может превысить M.
5. **Не завершиться после `fail`.** По условию нужно сразу выйти, иначе вердикт может быть любым.
6. **Неверный формат ответа.** Нужна строка `! N`, с восклицательным знаком и пробелом.
7. **Ошибка на единицу в границах.** После удвоения N лежит в `(prev, h]`. Левая граница
   поиска — `prev + 1`, а не `prev`.
