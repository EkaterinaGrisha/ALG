## Как устроен каждый разбор

1. **Условие простыми словами.** Что на самом деле просят, без «легенды».
2. **Краткая теория.** Понятия и приёмы, без которых решение не понять.
3. **Суть решения.** Главная идея словами, без кода.
4. **Логика по шагам с трассировкой.** Решение «вручную» на примере из условия,
   со всеми промежуточными значениями (они получены реальным запуском кода).
5. **Код.** Тот же, что лежит в репозитории.
6. **Построчный разбор кода.** Что делает каждая строка и зачем.
7. **Сложность.** Сколько времени и памяти нужно и почему это укладывается в ограничения.
8. **Частые ошибки.** На чём обычно спотыкаются.

## Общие понятия, которые встречаются во всех разборах

### Сложность алгоритма и «O-большое»

**Сложность** — это оценка того, как растёт время работы (или память) программы
при росте входных данных. Её записывают как `O(f(n))`, что читается
«о большое от f от n». Запись означает: «количество действий растёт не быстрее,
чем f(n), умноженное на какую-то постоянную».

- `O(1)` — время не зависит от размера входа (например, сложить два числа).
- `O(log n)` — время растёт очень медленно: при n = 10¹⁸ это всего около 60 шагов.
  Так работает двоичный поиск: каждый шаг делит область поиска пополам.
- `O(n)` — один проход по данным.
- `O(n log n)` — примерно столько стоит сортировка.
- `O(n²)` — два вложенных цикла по n; при n = 10⁵ это уже 10¹⁰ действий, слишком много.

### Как по ограничениям понять, какая сложность нужна

Компьютер на C++ делает примерно 10⁸–10⁹ простых операций в секунду. Python
(обычный, CPython) медленнее примерно в 30–50 раз, то есть около 10⁷ операций в
секунду. PyPy (см. ниже) обычно в 5–20 раз быстрее CPython на циклах.

Отсюда грубая шпаргалка для Python при лимите 1–2 секунды:

| Размер n | Допустимая сложность |
|----------|----------------------|
| n ≤ 20 | перебор подмножеств `O(2ⁿ · n)` |
| n ≤ 500 | `O(n³)` |
| n ≤ 5 000 | `O(n²)` |
| n ≤ 10⁵ – 10⁶ | `O(n)` или `O(n log n)` |
| n ≤ 10¹⁸ | `O(log n)` или `O(1)`, только формулы и двоичный поиск |

### CPython и PyPy: какой Python выбирать

- **CPython** (в системе пишется как «Python 3.13.2») — стандартный интерпретатор.
  Удобный, но циклы в нём медленные.
- **PyPy** (в системе «Python 3.11 (PyPy 7.3.19)») — другой интерпретатор того же
  языка. У него есть **JIT-компилятор** (Just-In-Time, «компиляция на лету»): часто
  выполняемые циклы он переводит в машинный код прямо во время работы программы.
  Поэтому тяжёлые циклы на PyPy работают в 5–20 раз быстрее.

Правило: если в решении миллионы итераций Python-циклов (задачи 6 и 7), выбирайте
**PyPy**. Задача 6 на тестировании упала по времени именно потому, что была
отправлена на CPython.

### Быстрый ввод в Python

Во всех решениях ввод читается одной строкой:

```python
data = sys.stdin.buffer.read().split()
```

- `sys.stdin.buffer` — стандартный ввод в виде «сырых» байтов (без перевода в текст,
  это быстрее).
- `.read()` читает весь ввод целиком за одну операцию.
- `.split()` режет его по пробелам и переводам строк на отдельные «слова» (токены).

Дальше токены превращаются в числа функцией `int(...)`. Это в разы быстрее, чем
вызывать `input()` миллион раз.

### Целочисленное деление и остаток

- `a // b` — целая часть от деления (`7 // 2 = 3`).
- `a % b` — остаток от деления (`7 % 2 = 1`).
- В Python целые числа не переполняются: можно спокойно работать с 10¹⁸ и больше.
  В C++ и Java для таких чисел нужен 64-битный тип (`long long` / `long`).
