## 1. Условие простыми словами

Есть **реестр работ** скульпторов: каждая строка — один день работы над заказом. Поля:

| Поле | Смысл |
|------|-------|
| `day` | дата (ГГГГ-ММ-ДД) |
| `worker_id`, `rang` | кто работал (мастер/подмастерье) — для решения не нужны |
| `order_id` | номер заказа |
| `phase` | фаза: принятие заказа → эскиз → черновой обтёс → детализация → шлифовка и полировка |
| `activity` | постановка задачи / работа / демонстрация |
| `res` | итог демонстрации: `success`, `remake` (переделать), `stop` (отказ от заказа) |
| `pay` | при постановке — предварительная сумма; при успешной демонстрации — итоговая |

Мудрец утверждает, что полный срок заказа можно предсказать по фазе **эскиза**:

```
A + B·T₁ + C·R + D·dM = T
```

- `T` — полный срок заказа (дней от начала до конца) / 365;
- `T₁` — длительность эскиза / 365;
- `R` — число переделок эскиза / 10;
- `dM` — (итоговая − предварительная сумма за эскиз) / 1000.

На вход: коэффициенты A, B, C, D и реестр. Нужно проверить формулу **парным t-тестом**
(ошибка, если p < 0,1) на успешно завершённых заказах. Если формула верна, вывести `YES`.
Если нет — ошибочен ровно один коэффициент: назвать его и найти значение, при котором
**среднеквадратичная ошибка (MSE)** минимальна. Например, `C 0.2922`.

## 2. Краткая теория

### 2.1. Реестр как журнал событий и агрегирование

Строки реестра — это **события**. Чтобы получить по одному числу на заказ, события
**группируют** по `order_id` и вычисляют сводные величины: минимальную и максимальную дату,
количество переделок, суммы. Такая операция называется **агрегированием**. В pandas это
`groupby`, у нас — словарь «заказ → сводка».

### 2.2. Успешный заказ

Заказ завершён успешно, если в фазе «шлифовка и полировка» была демонстрация с итогом
`success`. Отменённые (`stop`) и брошенные (без финальной демонстрации) заказы не имеют
полного срока, поэтому в расчёт не идут.

### 2.3. Нормировка

**Нормировка** — деление на «характерный масштаб», чтобы величины были сравнимого размера:
дни делим на 365, переделки на 10, деньги на 1000. Без неё коэффициенты при днях и
деньгах отличались бы на порядки.

### 2.4. Линейная модель и MSE

Формула мудреца — **линейная модель**: прогноз = сумма признаков, умноженных на коэффициенты.
Качество прогноза меряют **среднеквадратичной ошибкой**:

```
MSE = (1/n) · Σ (yᵢ − ŷᵢ)²
```

Здесь yᵢ — настоящее значение, ŷᵢ — прогноз. Квадрат делает ошибки положительными и
сильнее наказывает большие промахи.

### 2.5. Метод наименьших квадратов для одного коэффициента

Пусть ошибочен коэффициент при признаке x (для A «признак» — константа 1). Остальные
коэффициенты фиксированы. Обозначим rᵢ = yᵢ − (прогноз без вклада этого коэффициента).
Нужно найти c, минимизирующее `Σ (rᵢ − c·xᵢ)²`. Это парабола по c. Её минимум там, где
производная равна нулю:

```
d/dc Σ (rᵢ − c·xᵢ)² = −2 Σ xᵢ (rᵢ − c·xᵢ) = 0   ⇒   c = Σ xᵢ rᵢ / Σ xᵢ²
```

Это и есть **метод наименьших квадратов** (МНК) в самом простом виде, по одной переменной.
Значение вычисляется точно, без перебора.

### 2.6. Парный t-критерий Стьюдента

Есть пары (настоящее yᵢ, прогноз ŷᵢ). Посчитаем разности dᵢ = yᵢ − ŷᵢ. Если формула
верна, разности — это случайный шум со **средним 0**. Если формула систематически
завышает или занижает, среднее разностей заметно отличается от 0.

**Парный t-тест** проверяет гипотезу «среднее разностей = 0»:

```
t = mean(d) / (s / √n)
```

Здесь s — стандартное отклонение разностей (насколько они разбросаны), n — число пар.
**p-значение** — вероятность увидеть такое же или ещё большее |t| при условии, что формула
верна. Маленькое p (< 0,1) означает, что расхождение не похоже на случайность, и формулу
признаём ошибочной. В Python это `scipy.stats.ttest_rel(y, y_mod)`.

Важно: t-тест замечает только **сдвиг в среднем**. Ошибка в коэффициенте, который
сдвигает прогноз несистематически, может тестом не обнаружиться. Так и задумано условием.

### 2.7. Почему выбирать по MSE, а не по t-тесту

Если подобрать **A** по МНК, среднее остатков становится ровно 0, и t-тест проходит
**всегда** (t = 0, p = 1). Значит, «какой коэффициент после подбора проходит t-тест» не
различает варианты. Правильный критерий — у какого коэффициента после подбора **MSE
меньше всего**. Неверный коэффициент, исправленный, объясняет данные почти идеально, а
подгонка верного коэффициента компенсирует ошибку лишь частично.

Дополнительно используем гарантию условия: модуль суммы верных коэффициентов ≤ 10.
Кандидаты, нарушающие её, отбрасываются.

### 2.8. Потоковая обработка

Реестр может быть огромным, а памяти 128 МБ. Поэтому строки не хранятся все сразу. Каждая
строка сразу учитывается в сводке своего заказа, и в памяти остаются только сводки.

## 3. Суть решения (без кода)

1. Читаем коэффициенты, затем заголовок таблицы. Разделитель определяем по заголовку,
   столбцы находим по именам.
2. Идём по строкам и для каждого заказа копим:
   - первый и последний день заказа;
   - флаг «был финальный `success`»;
   - первый и последний день эскиза;
   - число переделок эскиза;
   - предварительную и итоговую сумму эскиза.
3. Для успешных заказов вычисляем нормированные T, T₁, R, dM.
4. Прогноз по формуле, парный t-тест. Если p ≥ 0,1, печатаем `YES`.
5. Иначе для каждого из 4 коэффициентов находим МНК-значение и MSE. Выбираем
   коэффициент с наименьшей MSE (среди удовлетворяющих |сумма| ≤ 10) и печатаем его
   имя и значение.

## 4. Логика по шагам с трассировкой

Синтетический реестр (сгенерирован по описанию условия). Истинная формула:
`0.4 + 2.0·T₁ + 0.3·R + 0.1·dM`, а мудрецу дали `C = 0.9` вместо `0.3`.

### 4.1. Один заказ

Строки заказа 56 (дни «работы» вне эскиза опущены):

```
2021-12-20  принятие заказа       постановка задачи          171
2021-12-21  принятие заказа       демонстрация      success  239
2021-12-22  эскиз                 постановка задачи          238   ← начало эскиза, предв. сумма
2021-12-23  эскиз                 работа
2021-12-24  эскиз                 демонстрация      remake         ← переделка №1
2021-12-25 … 2021-12-28  эскиз    работа
2021-12-29  эскиз                 демонстрация      success  138   ← конец эскиза, итог. сумма
...
2022-04-13  шлифовка и полировка  постановка задачи         1212
2022-06-04  шлифовка и полировка  демонстрация      success  540   ← заказ завершён успешно
```

| Величина | Расчёт | Значение | Нормировано |
|----------|--------|----------|-------------|
| T | 2022-06-04 − 2021-12-20 | 166 дней | 166/365 = 0,4548 |
| T₁ | 2021-12-29 − 2021-12-22 | 7 дней | 7/365 = 0,0192 |
| R | одна демонстрация `remake` в эскизе | 1 | 1/10 = 0,1 |
| dM | 138 − 238 | −100 | −100/1000 = −0,100 |

Прогноз по **истинной** формуле: 0,4 + 2·0,0192 + 0,3·0,1 + 0,1·(−0,1) = **0,4584** (факт 0,4548).
По формуле **мудреца** (C = 0,9): **0,5184**, то есть заметное завышение.

### 4.2. Весь датасет (45 успешных заказов)

- Среднее факта y = 0,4748, среднее прогноза = 0,5187.
- t = −3,384, **p = 0,0015 < 0,1** → формула ошибочна.

Подбор каждого коэффициента по МНК:

| Подбираем | Лучшее значение | MSE после подбора |
|-----------|-----------------|-------------------|
| A | 0,3560 | 0,007420 |
| B | −1,0011 | 0,001803 |
| **C** | **0,2922** | **0,000077** ← минимум |
| D | −0,1667 | 0,006591 |

MSE исходной формулы — 0,009352. Подбор C снижает ошибку в ~120 раз, остальные — в
1,3–5 раз. Ответ программы: `C 0.2922473027` (истинное значение 0,3; разница — шум данных).

## 5. Код

```python
import csv
import math
import re
import sys
from datetime import date

T0, R0, DM0 = 365.0, 10.0, 1000.0
NAMES = "ABCD"


def norm(s):
    return (s or "").strip().lower().replace("ё", "е")


def phase_code(s):
    s = norm(s)
    if "прин" in s:
        return 0          # принятие заказа
    if "эскиз" in s:
        return 1          # эскиз
    if "обт" in s or "черн" in s:
        return 2          # черновой обтёс
    if "детал" in s:
        return 3          # детализация
    if "шлиф" in s or "полир" in s:
        return 4          # шлифовка и полировка
    return -1


def activity_code(s):
    s = norm(s)
    if "постан" in s:
        return "set"      # постановка задачи
    if "демонстр" in s:
        return "demo"     # демонстрация
    return "work"         # работа


def to_float(s):
    s = (s or "").strip().replace(",", ".")
    try:
        v = float(s)
        return 0.0 if math.isnan(v) else v
    except ValueError:
        return 0.0


def to_day(s):
    return date.fromisoformat((s or "").strip()[:10]).toordinal()


# ---------- парный t-тест: scipy, а если его нет — своя реализация ----------
def betacf(a, b, x):
    # непрерывная дробь для неполной бета-функции (метод Ленца)
    tiny = 1e-300
    qab, qap, qam = a + b, a + 1.0, a - 1.0
    c, d = 1.0, 1.0 - qab * x / qap
    d = 1.0 / (d if abs(d) > tiny else tiny)
    h = d
    for m in range(1, 1000):
        m2 = 2 * m
        aa = m * (b - m) * x / ((qam + m2) * (a + m2))
        d = 1.0 + aa * d
        d = 1.0 / (d if abs(d) > tiny else tiny)
        c = 1.0 + aa / c
        c = c if abs(c) > tiny else tiny
        h *= d * c
        aa = -(a + m) * (qab + m) * x / ((a + m2) * (qap + m2))
        d = 1.0 + aa * d
        d = 1.0 / (d if abs(d) > tiny else tiny)
        c = 1.0 + aa / c
        c = c if abs(c) > tiny else tiny
        delta = d * c
        h *= delta
        if abs(delta - 1.0) < 1e-15:
            break
    return h


def betainc(a, b, x):
    if x <= 0.0:
        return 0.0
    if x >= 1.0:
        return 1.0
    lbt = math.lgamma(a + b) - math.lgamma(a) - math.lgamma(b) + a * math.log(x) + b * math.log(1.0 - x)
    if x < (a + 1.0) / (a + b + 2.0):
        return math.exp(lbt) * betacf(a, b, x) / a
    return 1.0 - math.exp(lbt) * betacf(b, a, 1.0 - x) / b


def paired_ttest_p(y, y_mod):
    try:
        from scipy.stats import ttest_rel
        return float(ttest_rel(y, y_mod)[1])
    except ImportError:
        pass
    d = [u - v for u, v in zip(y, y_mod)]
    n = len(d)
    if n < 2:
        return float("nan")
    mean = sum(d) / n
    var = sum((x - mean) ** 2 for x in d) / (n - 1)
    if var == 0.0:
        return float("nan") if mean == 0.0 else 0.0
    t = mean / math.sqrt(var / n)
    df = n - 1
    return betainc(df / 2.0, 0.5, df / (df + t * t))


# ---------- чтение и подготовка данных (потоково, по одной строке) ----------
NUM = re.compile(r"[-+]?(?:\d+(?:[.,]\d*)?|[.,]\d+)(?:[eE][-+]?\d+)?")


def read_input():
    stream = iter(sys.stdin)
    line = ""
    for line in stream:
        if line.strip():
            break
    coefs = [float(x.replace(",", ".")) for x in NUM.findall(line)][:4]
    header_line = ""
    for header_line in stream:
        if header_line.strip():
            break
    delim = max([",", "\t", ";", "|"], key=header_line.count)
    header = [norm(h) for h in next(csv.reader([header_line], delimiter=delim))]
    return coefs, header, split_rows(stream, delim)


def split_rows(stream, delim):
    # быстрый путь: строка без кавычек режется обычным split, иначе — модулем csv
    for ln in stream:
        if '"' in ln:
            yield next(csv.reader([ln], delimiter=delim))
        else:
            s = ln.rstrip("\r\n")
            if s and not s.isspace():
                yield s.split(delim)


def build_features(header, rows):
    def col(name):
        for k, h in enumerate(header):
            if h == name:
                return k
        for k, h in enumerate(header):
            if name in h:
                return k
        raise KeyError(name)

    c_day, c_ord, c_ph = col("day"), col("order_id"), col("phase")
    c_act, c_res, c_pay = col("activity"), col("res"), col("pay")
    need = max(c_day, c_ord, c_ph, c_act, c_res, c_pay) + 1

    ph_cache, act_cache, day_cache = {}, {}, {}
    # по заказу: [min_day, max_day, done, s_min, s_max, remakes, pre_day, pre_pay, fin_pay]
    orders = {}
    remake_seen = set()      # дубликаты демонстраций-переделок не считаем дважды
    for r in rows:
        if len(r) < need:
            r = r + [""] * (need - len(r))
        ds = r[c_day]
        day = day_cache.get(ds)
        if day is None:
            try:
                day = to_day(ds)
            except ValueError:
                continue
            day_cache[ds] = day
        ph = ph_cache.get(r[c_ph])
        if ph is None:
            ph = ph_cache[r[c_ph]] = phase_code(r[c_ph])
        act = act_cache.get(r[c_act])
        if act is None:
            act = act_cache[r[c_act]] = activity_code(r[c_act])
        oid = r[c_ord].strip()
        o = orders.get(oid)
        if o is None:
            o = orders[oid] = [day, day, False, None, None, 0, None, 0.0, None]
        if day < o[0]:
            o[0] = day
        if day > o[1]:
            o[1] = day
        if (act != "demo" and act != "set") or ph not in (1, 4):
            if ph == 1:
                if o[3] is None or day < o[3]:
                    o[3] = day
                if o[4] is None or day > o[4]:
                    o[4] = day
            continue
        res = norm(r[c_res])
        if ph == 4:
            if act == "demo" and res == "success":
                o[2] = True
            continue
        # фаза эскиза
        if o[3] is None or day < o[3]:
            o[3] = day
        if o[4] is None or day > o[4]:
            o[4] = day
        if act == "set":
            if o[6] is None or day < o[6]:
                o[6] = day
                o[7] = to_float(r[c_pay])
        elif res == "remake":
            key = (oid, day)
            if key not in remake_seen:
                remake_seen.add(key)
                o[5] += 1
        elif res == "success":
            o[8] = to_float(r[c_pay])

    X, y = [], []
    for o in orders.values():
        if not o[2] or o[3] is None:
            continue                         # прерванные и брошенные заказы не берём
        T = o[1] - o[0]
        T1 = o[4] - o[3]
        dM = (o[8] if o[8] is not None else 0.0) - o[7]
        X.append((1.0, T1 / T0, o[5] / R0, dM / DM0))
        y.append(T / T0)
    return X, y


def main():
    coefs, header, rows = read_input()
    X, y = build_features(header, rows)

    y_mod = [sum(c * x for c, x in zip(coefs, row)) for row in X]
    p = paired_ttest_p(y, y_mod)
    if not (p < 0.1):                        # p >= 0.1 (или nan: прогноз совпал идеально)
        print("YES")
        return

    # Ошибочен ровно один коэффициент: для каждого подбираем значение,
    # минимизирующее MSE при остальных фиксированных (МНК по одной переменной),
    # и выбираем тот, у которого MSE получается наименьшей.
    best = None
    for k in range(4):
        num = den = 0.0
        for row, yy, pm in zip(X, y, y_mod):
            xk = row[k]
            r = yy - (pm - coefs[k] * xk)    # что должен объяснить коэффициент k
            num += xk * r
            den += xk * xk
        if den == 0.0:
            continue
        val = num / den
        new = coefs[:]
        new[k] = val
        mse = sum((yy - sum(c * x for c, x in zip(new, row))) ** 2 for row, yy in zip(X, y)) / len(y)
        ok_sum = abs(sum(new)) <= 10 + 1e-9  # гарантия условия для верных коэффициентов
        cand = (not ok_sum, mse, k, val)
        if best is None or cand < best:
            best = cand
    _, _, k, val = best
    print("%s %.10f" % (NAMES[k], val))  # без округления до 3 знаков


if __name__ == "__main__":
    main()
```

### 6.2. t-тест

```python
def paired_ttest_p(y, y_mod):
    try:
        from scipy.stats import ttest_rel
        return float(ttest_rel(y, y_mod)[1])
    except ImportError:
        pass
```

- Основной путь — `ttest_rel` из scipy, как предписывает условие. `[1]` — это p-значение.

```python
    d = [u - v for u, v in zip(y, y_mod)]
    n = len(d)
    ...
    mean = sum(d) / n
    var = sum((x - mean) ** 2 for x in d) / (n - 1)
    ...
    t = mean / math.sqrt(var / n)
    df = n - 1
    return betainc(df / 2.0, 0.5, df / (df + t * t))
```

- Запасной путь на случай, если scipy нет. Считаем t по формуле из 2.6.
- Двустороннее p-значение распределения Стьюдента с `df` степенями свободы выражается
  через **регуляризованную неполную бета-функцию** `I_x(df/2, 1/2)` при `x = df/(df + t²)`.
- `betainc` и `betacf` вычисляют её непрерывной дробью (метод Ленца). С результатом
  scipy это совпадает с точностью ~10⁻¹¹.
- Если все разности одинаковы (дисперсия 0), тест не определён: при нулевом среднем
  возвращаем `nan` (формула идеальна), иначе 0.

```python
def split_rows(stream, delim):
    for ln in stream:
        if '"' in ln:
            yield next(csv.reader([ln], delimiter=delim))
        else:
            s = ln.rstrip("\r\n")
            if s and not s.isspace():
                yield s.split(delim)
```

### 6.5. Главная функция

```python
    y_mod = [sum(c * x for c, x in zip(coefs, row)) for row in X]
    p = paired_ttest_p(y, y_mod)
    if not (p < 0.1):
        print("YES")
        return
```

- Прогноз для каждого заказа и t-тест. Запись `not (p < 0.1)` верна и для `nan`
  (`nan < 0.1` ложно), то есть идеальный прогноз даёт `YES`.

```python
    for k in range(4):
        num = den = 0.0
        for row, yy, pm in zip(X, y, y_mod):
            xk = row[k]
            r = yy - (pm - coefs[k] * xk)
            num += xk * r
            den += xk * xk
        if den == 0.0:
            continue
        val = num / den
```

- Для коэффициента k: `pm − coefs[k]·xk` — прогноз **без** его вклада, `r` — остаток,
  который должен объяснить коэффициент. `val = Σ x·r / Σ x²` — формула МНК из 2.5.
- Если признак везде 0 (`den == 0`), коэффициент не влияет на прогноз и подобрать его нельзя.

```python
        new = coefs[:]
        new[k] = val
        mse = sum((yy - sum(c * x for c, x in zip(new, row))) ** 2 for row, yy in zip(X, y)) / len(y)

```

- MSE формулы с исправленным коэффициентом.
- Кортежи сравниваются слева направо. Поэтому сначала выигрывает кандидат, у которого
  выполнено |сумма| ≤ 10 (`not ok_sum` = False меньше True), а среди них — с меньшей MSE.

## 7. Сложность

- **Время:** один проход по строкам реестра, `O(N)` для N строк. На каждую строку — несколько
  обращений к словарям. Затем `O(M)` для M успешных заказов (t-тест и 4 подбора).
  3,7 млн строк (313 МБ) обрабатываются за ~4,9 с, датасет обычного размера — за доли секунды.
- **Память:** `O(число заказов)`, строки не хранятся: ~23 МБ даже на 3,7 млн строк
  (~100 МБ, если импортируется scipy, при лимите 128 МБ).

## 8. Частые ошибки

1. **Считать по всем заказам**, включая отменённые и брошенные. У них нет полного срока.
2. **Путать начало заказа.** Если фазы «принятие заказа» нет, заказ начинается с эскиза.
   Поэтому берём минимум дат всех строк заказа.
3. **Не нормировать** или нормировать не на те величины (365 / 10 / 1000).
4. **Выбирать ошибочный коэффициент по t-тесту.** Подбор A всегда даёт p = 1.
5. **Подбирать перебором с шагом 0,001.** Медленно и неточно, когда есть точная формула МНК.
6. **Округлять ответ до 3 знаков.** Условие просит не округлять, а система смотрит первые 3 знака.
7. **Держать весь реестр в памяти** (например, `pandas.read_csv` целиком на огромном файле
   при лимите 128 МБ).
8. **Жёстко зашить порядок столбцов или разделитель.** Надёжнее искать столбцы по именам.
